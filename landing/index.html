Minimal · Fast · Native

A lightweight, native database client.

SBDb brings connection management, database exploration, table inspection and data editing into one focused desktop workspace. Built with Go and a native UI for the everyday database work you do most.

Why SBDb

Everyday database work, without the heavyweight IDE.

Most days you connect, browse a schema, check a table, fix a few values and run some SQL. SBDb is inspired by familiar DBeaver workflows, but it focuses only on those tasks and keeps a small memory footprint and a clean interface.

  • Native desktop UI

    Built with Go and MyGo Native UI. No embedded browser powers the interface.

  • Loads data as needed

    Paginated table reads with 100 rows per page by default and a bounded page cache.

  • Connects on demand

    Startup only loads local configuration. Database connections open when you ask for them.

  • Stays responsive

    Database operations run outside the UI rendering path, so the window keeps working while queries run.

  • Stays local

    Settings and connection profiles live on your machine. Passwords go to the operating system credential store, never into plaintext JSON.

Features

Everything for the core workflow, nothing you don't need.

Connection management

Saved profiles organized in folders, connection testing, TLS options, and connect or disconnect whenever you need.

Database explorer

Browse the connected database, schemas, tables and views. Metadata loads lazily as you expand the tree.

Table Inspector

See data next to columns, constraints, foreign keys, indexes and triggers in one tab.

Fast data grid

Virtualized rows, server-side pagination, sorting, and a column filter that runs on the database server.

Safe, explicit editing

Stage cell edits locally, then Save or Revert. Saves run in a transaction and check for conflicting changes. Views and tables without a reliable row identity stay read-only.

SQL workspace & files

Syntax highlighting, line numbers, a separate session per tab, run the selection or current statement, cancel anytime. Open and save local .sql files safely.

Plus tabbed workspaces, Light, Dark and System themes, and a remembered window size and sidebar width.

How it works

From connection to saved change in three steps.

  1. 01

    Add a connection

    Create a PostgreSQL profile, test it, and keep it in a folder. The password goes to your OS credential store.

  2. 02

    Browse & inspect

    Expand schemas in the explorer and open a table to see its data and structure side by side.

  3. 03

    Edit or query, then save

    Stage edits in the grid and save them in one transaction, or open a SQL tab and run with Ctrl+Enter.

Run from source

Install the Go toolchain declared in the project's go.mod (currently Go 1.27.2), clone the repository, and launch the app from its root. You only need a PostgreSQL server to browse real data, not to open the app.

# clone and run
git clone https://github.com/congthien2003/dbl.git
cd dbl
go run .

FAQ

Questions, answered.

Is SBDb a full DBeaver replacement?

No. It follows familiar DBeaver workflows but only covers the tasks used most often: connections, navigation, table inspection, data viewing and editing, SQL execution, and local SQL files.

Where are my passwords stored?

In your operating system's credential store. Connection profiles in ~/.dbl/ never contain plaintext passwords. If secure storage isn't available, SBDb asks for the password for the current session instead of saving it.

Does it use an embedded browser like Electron?

No. The interface is built with Go and MyGo Native UI, without an embedded browser.

Will my edits be written immediately?

No. Edits are staged locally until you choose Save, which applies them in a transaction and checks for conflicting changes. If a save fails, your pending edits are kept.

Is it ready for daily use?

SBDb is under active development. The PostgreSQL workflow is implemented; other engines, platform validation and distribution packages are on the roadmap. Today you run it from source.

What is intentionally left out?

To stay small, the initial scope excludes visual query builders, ER diagrams, migration management, backup and restore, import/export, and AI-assisted SQL.
